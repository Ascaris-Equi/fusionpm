# Reproducible benchmark workflow

This directory records the commands, configuration, overlap definition, and
machine-readable outputs used for the iScience revision. Raw benchmark data
are not silently regenerated by the training script: the exact supplied CSVs
are identified by row count and SHA-256 in the generated dataset manifest.

## 1. Environment

Create an isolated environment and install the declared packages:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r benchmark/requirements.txt
```

For CUDA inference, install the PyTorch build appropriate for the local CUDA
driver by following the official PyTorch selector before installing the
remaining requirements.

## 2. Required data layout

Place the supplied, unmodified split files under `dataset/`:

```text
dataset/
├── train_data_fold0.csv ... train_data_fold4.csv
├── val_data_fold0.csv   ... val_data_fold4.csv
├── independent_set.csv
├── external_set.csv
└── common_hla.csv
```

Each model-ready CSV must contain `peptide`, `HLA_sequence`, and `label`.
The exact split files used in a run are recorded in
`benchmark/results/dataset_manifest.csv`, including SHA-256 hashes.

Source commits and the current split-generation limitation are documented in
[`DATA_PROVENANCE.md`](DATA_PROVENANCE.md). The repository reproduces
model-side preprocessing of frozen CSV inputs whose source snapshot, retrieval
date, row count, byte count, and SHA-256 are recorded there.

## 3. Inference

Run the released five-checkpoint probability average on the independent test
set:

```bash
python infer.py \
  --input dataset/independent_set.csv \
  --output benchmark/results/independent_predictions.csv \
  --device auto \
  --threshold 0.5
```

The model and evaluation settings are also recorded in
`configs/iscience_revision.json`.

The released validation CSVs contain the same normalized row multiset and do
not form conventional disjoint cross-validation folds. This upstream behavior
and the measured overlap are documented in
[`DATA_PROVENANCE.md`](DATA_PROVENANCE.md) and
[`results/split_audit.md`](results/split_audit.md). “Five-checkpoint average”
therefore describes the inference operation more accurately than an unbiased
five-fold cross-validation estimate.

Before inference, audit that every supplied train/validation fold is the
intended file and quantify any split overlap:

```bash
python benchmark/verify_splits.py \
  --train-glob "dataset/train_data_fold*.csv" \
  --validation-glob "dataset/val_data_fold*.csv" \
  --output-dir benchmark/results
```

## 4. Training-overlap analysis

Generate both machine-readable metrics and the GitHub-rendered table:

```bash
python benchmark/evaluate_seen_unseen.py \
  --train-glob "dataset/train_data_fold*.csv" \
  --validation-glob "dataset/val_data_fold*.csv" \
  --test-input dataset/independent_set.csv \
  --predictions benchmark/results/independent_predictions.csv \
  --output-dir benchmark/results \
  --threshold 0.5
```

The primary comparison defines a sample as **seen** only when the exact
normalized `(peptide, HLA_sequence)` pair occurs in the union of the five
training CSVs. Normalization strips surrounding whitespace and converts both
fields to uppercase. The additional five-way breakdown distinguishes:

1. exact pair seen;
2. peptide and HLA both seen, but never as that pair;
3. peptide seen and HLA unseen;
4. peptide unseen and HLA seen;
5. both unseen.

This distinction prevents performance on a familiar allele from being
misreported as performance on a previously observed pMHC pair.

## 5. Baseline provenance

`baseline_versions.csv` is the provenance table for the 15 Fusion-pM
baselines. Thirteen metric rows are taken from the official Chu et al. (2022)
Figure 4 source workbook, HLAthena is linked to its separate published method
article because it is absent from that workbook, and HLA-Inception
(`source = local`) is the only author-run baseline. The table records the
reported method release, exact immutable result source, access date, worksheet
cell range, published metric vector, and reproduction note. Fusion-pM itself
is the proposed method and is not included as a baseline row.

The same information is rendered as a GitHub table in
[`BASELINE_PROVENANCE.md`](BASELINE_PROVENANCE.md).

Checkpoint hashes and the exact parameter count are recorded in
[`MODEL_PROVENANCE.md`](MODEL_PROVENANCE.md). Verified HLA-Inception release
behavior and the status of its run-specific metadata are recorded in
[`HLA_INCEPTION_PROVENANCE.md`](HLA_INCEPTION_PROVENANCE.md).

## 6. Outputs

`benchmark/results/README.md` is generated, not hand-edited, and is suitable
for direct display on GitHub. The corresponding CSV and JSON files are the
authoritative values for downstream manuscript tables and response letters.
