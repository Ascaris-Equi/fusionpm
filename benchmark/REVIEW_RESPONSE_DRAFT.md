## Editor: complete benchmark workflow

**Response.** We expanded the public repository with a revision-specific
benchmark workflow. The repository now records the model configuration,
inference and evaluation commands, exact overlap definition, metric code,
split-file audit, SHA-256 data manifest, dependency versions, and a provenance
table for local baselines and web-server results. Web-server provenance
includes the server/model version, access date, supported-row count, and raw
output reference. The generated Markdown tables are backed by machine-readable
CSV/JSON files and are not manually transcribed.

**Remaining item before this response can be used verbatim.** The supplied CSV
splits are traced to the TransPHLA data release, but the current Fusion-pM
repository still needs either (i) the original split-generation program and
raw source inputs, or (ii) an explicit statement that the frozen upstream
splits are inputs rather than outputs generated by this repository. The
original five-fold generation step must not be claimed as reproduced until
that source is added.

## Editor: tone down translational claims

**Response.** We revised the manuscript to describe Fusion-pM as a
computational prioritization tool for peptide–HLA binding candidates. We no
longer infer population protection, broad-spectrum vaccine efficacy, or
personalized immunotherapy benefit from binding predictions alone. We also
state that the present independent set contains no HLA sequence absent from
the training union, so the new analysis does not establish unseen-allele or
population-level coverage. All predicted candidates require experimental
validation.

Suggested replacement language:

> Fusion-pM may support computational prioritization of candidate peptides for
> downstream experimental evaluation. Binding predictions alone do not
> establish immunogenicity, vaccine protection, clinical benefit, or coverage
> across unobserved HLA alleles.

## Reviewer 1: training-seen versus training-unseen test performance

**Response.** We added a training-overlap analysis of the independent test
set. Peptide and HLA pseudo-sequences were normalized by stripping surrounding
whitespace and converting to uppercase. A test row was defined as
training-seen only when its exact `(peptide, HLA_sequence)` pair occurred in
the union of all five training CSVs.

Of 171,438 independent test rows, 170,596 (99.51%) were exact-pair unseen and
842 (0.49%) were seen. On the unseen subset, Fusion-pM achieved ROC-AUC 0.9859,
AUPR 0.9858, accuracy 0.9442, MCC 0.8883, and F1 0.9441. The corresponding
overall values were 0.9860, 0.9860, 0.9444, 0.8888, and 0.9446, respectively.
Thus, excluding exact training overlaps produced no material reduction in the
independent-set performance.

The seen subset was small and strongly imbalanced (833/842 positives;
98.93%), so its accuracy and AUPR are not directly comparable with those of
the nearly balanced unseen subset. We therefore report sample counts,
positive prevalence, ROC-AUC, AUPR, accuracy, MCC, and F1 together rather than
highlighting a single metric.

We additionally separated component-level novelty. Among 110,742 rows with an
unseen peptide and a seen HLA sequence, ROC-AUC was 0.9827 and AUPR was 0.9701.
Among 59,854 rows for which both components had been seen but never as that
exact pair, ROC-AUC was 0.9866 and AUPR was 0.9961. No independent-test row
contained an HLA sequence absent from the training union; consequently, these
results support generalization to new peptides and new peptide–HLA pairings,
but not to unseen HLA alleles.

The full table, code, overlap definition, and file hashes are provided under
`benchmark/results/` in the repository.
